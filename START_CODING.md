## 2. Git & Branching Protocol

- **Protected Branch:** `main`. **Never commit, rebase, or push directly to `main`.**
- **Active Feature Branch:** `feature/initial-implementation`.
- **Workflow for New Tasks:**
  ```bash
  git checkout feature/initial-implementation
  git checkout -b feat/task-name
  # Implement code with tests (TDD)
  .venv/bin/python -m pytest tests/
  git add <touched_files>
  git commit -m "feat: implement layer 15 relative velocity tracker"
  # Never git push. Notify the lead researcher when ready.
  ```
- **Commit Format:** `<type>: <what changed>` where type is one of `feat`, `fix`, `docs`, `refactor`, `test`, `exp`.
- **Attribution Rule:** **Zero AI or Claude attribution anywhere** (no trailers, no commit notes, no comments).

## 3. Core Hypothesis, Metrics & Pre-Registered Criteria

### The Question
Can model-intrinsic dynamical instability metrics (relative velocity at Layer 15 + next-token entropy with $K=4$ persistence) detect mathematical reasoning errors and prune unproductive rollout branches without requiring an external Process Reward Model (PRM)?

### Key Performance Indicators (KPIs)
1. **Compute Reduction Ratio:** Total tokens generated to solve GSM8k subset vs Best-of-8 baseline (Target: $\le 35\%$ tokens, $> 2.8\times$ FLOP saving).
2. **Reasoning Accuracy:** Final pass@1 accuracy matching or exceeding Best-of-8 ($\ge 82\%$).
3. **False Positive Pruning Rate:** Fraction of ultimately correct trajectories pruned prematurely ($< 10\%$).
4. **Telemetry Latency Overhead:** Hidden-state velocity calculation time per token ($< 0.5\text{ ms}$, $< 1\%$ overhead).

### Pre-Registered Rules
- **Kill Criterion (Day 3 Gate):** If Lyapunov pruning discards $> 30\%$ of correct reasoning trajectories, dropping final accuracy below Greedy Decoding ($< 65\%$), kill immediately.
- **Pulse Criterion:** If the pruner matches Best-of-8 accuracy ($\ge 82\%$) while consuming $\le 35\%$ of total tokens generated by Best-of-8 on GSM8k, double down for MATH-500 scaling.
